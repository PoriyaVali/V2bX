# V2bX v1.9.1

این نسخه روند ویزارد را اصلاح می‌کند. ارتقا با دسترسی root:

```sh
v2bx update
```

برای همین نسخه: `v2bx update v1.9.1`. کانفیگ موجود با update بازنویسی نمی‌شود.
سپس گزینهٔ ۹ منو یا `V2bX configure` ویزارد مرحله‌ای را باز می‌کند.

- انتخاب mux، شناسه و هسته برای هر نود دستی باقی می‌ماند؛ هستهٔ انتخاب‌شدهٔ ادمین
  با انتخاب خودکار جایگزین نمی‌شود. Hysteria2 می‌تواند Sing یا هستهٔ اختصاصی خود
  را بگیرد؛ VLESS و VMess می‌توانند Sing یا Xray باشند.
- پس از انتخاب هسته، نوع نود، TLS/REALITY و دامنه از پنل پیدا و خلاصه می‌شوند.
  Enter تأیید می‌کند؛ `e` برای ویرایش و `n` برای لغو است. اشتباه در ID یا هسته
  امکان تلاش دوباره دارد، بدون تکرار تنظیمات عمومی.
- SNI داخل `tls_settings` در AnyTLS خوانده می‌شود؛ برای AnyTLS REALITY درخواست
  گواهی ساخته نمی‌شود. دامنهٔ موجود در پنل یا تنظیمات قبلی، دوباره پرسیده نمی‌شود.
- در برخورد ID مشترک بین پروتکل‌ها، انتخاب صریح از گزینه‌های پیدا‌شده لازم است.
  پاسخ ناقص، خطای شبکه یا احراز هویت، به حدس نوع نود تبدیل نمی‌شود. بررسی فقط
  endpoint خواندن config را با حداکثر سه درخواست هم‌زمان و بدون retry خودکار
  استفاده می‌کند.
- تنظیمات گواهی قبلی همان نود، شامل مسیرها، روش تمدید، حساب ACME و مشخصات DNS،
  حفظ می‌شوند. لغو، قطع ورودی یا شکست اعتبارسنجی، فایل فعال را جایگزین نمی‌کند.
- اجرای بدون سؤال همچنان `--nodes type:id,...` و `--core` دارد؛ انتخاب مستقل
  هستهٔ هر نود با `--node-cores vless:1=sing,hysteria2:2=hysteria2` اضافه شده است.
- VLESS با رمزگذاری افزوده به Xray نیاز دارد؛ انتخاب ناسازگار Sing پیش از ذخیره
  رد می‌شود و در حالت auto، Xray انتخاب می‌شود.
- اسکریپت منو، قابلیت `--guided` باینری را بررسی می‌کند. برای باینری قدیمی، ویزارد
  دستی قبلی باقی می‌ماند؛ `V2BX_MANUAL_WIZARD=1` آن را صریحاً انتخاب می‌کند.

اصلاحات امنیت، پایداری و نسخهٔ MDNS ریلیز v1.9.0 حفظ شده‌اند. این تغییر پروتکل یا
رمزگذاری کاربران را عوض نمی‌کند. [راهنمای ویزارد](../automated-setup.md) جزئیات روش
گواهی، محدودیت تشخیص و اجرای بدون سؤال را توضیح می‌دهد.
