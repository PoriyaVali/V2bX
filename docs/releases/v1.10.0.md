# V2bX v1.10.0 — هستهٔ سرور Mihomo و هماهنگی با Irboard

هستهٔ Mihomo اکنون داخل بیلد رسمی V2bX قرار دارد؛ نصب باینری جداگانهٔ Mihomo لازم نیست.
پس از ارتقا، برای نود موردنظر در ویزارد، هستهٔ `mihomo` را انتخاب کنید. ارتقا به‌تنهایی
هستهٔ نودهای موجود را تغییر نمی‌دهد.

## تغییرات

- پشتیبانی سروری چندکاربره از HTTP، SOCKS5، Mieru، ShadowQUIC، VMess، VLESS، Trojan،
  TUIC، Hysteria2، AnyTLS و TrustTunnel؛ همراه با شنود، احراز هویت و مصرف مستقل هر نود.
- هماهنگی با نودهای مدیریت‌شدهٔ Irboard: کاربران مجاز، آمار آپلود/دانلود، آنلاین‌ها،
  محدودیت سرعت/IP/اتصال و قطع دسترسی پس از مسدودی، انقضا یا اتمام حجم.
- نگهداری مصرف گزارش‌نشده، ارسال مجدد با شناسهٔ ثابت پس از گم‌شدن تأیید و حفظ
  اتصال موجود هنگام قطع موقت پنل؛ تغییر محدودیت سرعت در همان اتصال اعمال می‌شود.
- جداسازی نشست‌های UDP و مسیر پاسخ SOCKS/mux، حفظ TCP half-close و اصلاح مالکیت
  بافرهای smux در فورک Mihomo.
- بارگذاری گواهی معتبر با بررسی دامنه، تاریخ، کاربرد TLS Server و تطابق کلید؛
  فایل ناقص یا گواهی دامنهٔ اشتباه، آخرین جفت سالم را جایگزین نمی‌کند.
- اصلاح ثبت مصرف در Webman در نسخهٔ همراه Irboard؛ بدون این اصلاح، گزارش مصرف
  JSON می‌توانست با خطای `Invalid traffic JSON` رد شود.

## ارتقا

۱. از دیتابیس، تنظیمات و گواهی‌ها نسخهٔ پشتیبان بگیرید؛ Irboard را از `main` با
اسکریپت `update.sh` خودش ارتقا دهید تا ساختار جدول‌ها و اصلاح Webman اعمال شود.

۲. روی سرور نود، با دسترسی root:

```sh
v2bx update 1.10.0
v2bx menu
```

برای افزودن نود Mihomo از گزینهٔ ۹ استفاده کنید. ویزارد کانفیگ مجموعهٔ نودهای
انتخاب‌شده را می‌سازد؛ همهٔ نودهایی را که باید باقی بمانند وارد کنید. جزئیات
تنظیمات، دامنهٔ گواهی و پروتکل‌ها در [راهنمای Mihomo](../mihomo-server.md) آمده است.

۳. ابتدا یک نود آزمایشی را فعال کنید و اتصال، مصرف و آنلاین‌ها را بررسی کنید.
برگشت باینری: `v2bx update 1.9.4`. نسخهٔ قبلی هستهٔ `mihomo` را نمی‌شناسد؛ پیش از
برگشت، کانفیگ قبلی بدون این هسته را بازیابی کنید. برگشت دیتابیس پنل مستقل است و
باید بر اساس نسخهٔ پشتیبان انجام شود.

## اعتبارسنجی و محدوده

در استقرار ابری واقعی Webman، MariaDB، Redis، V2bX و کلاینت‌های جداگانه، ۳۵۴
بررسی یکتا موفق بودند: ۲۵ نوع نود پنل ساخته شد و ۱۴ نوع ورودی سروری اتصال واقعی
داشتند؛ شامل ۱۱ Mihomo، دو Sing و MDNS بومی. مصرف کاربران و آمار روزانهٔ هر ۱۴ نود
دقیقاً تطبیق کرد. [راهنمای بازتولید](../../scripts/e2e/mihomo/README.md) همراه سورس است.

- پوشش کامل محدودیت‌ها و UDP مربوط به ماتریس اصلی ۱۳ پروتکل است؛ HTTP ورودی UDP
  ندارد. آزمون بومی MDNS شامل TCP، مصرف، آنلاین‌ها و محافظت مقصد خصوصی بود؛ ماتریس
  کامل UDP و سیاست‌های زندهٔ آن در این اجرا بررسی نشده است.
- گواهی‌ها با CA خصوصی و بررسی واقعی hostname آزمایش شدند. صدور و تمدید ACME عمومی
  روی دامنهٔ واقعی همچنان به آزمون استقرار نیاز دارد؛ موفقیت CA محلی تأیید ACME نیست.
- تغییر عضویت کاربران، شنود همان نود Mihomo را بازسازی می‌کند و اتصال مجدد لازم است؛
  تغییر صرف محدودیت‌ها اتصال موجود را حفظ می‌کند.
- ۱۱ نوع دیگر کاتالوگ پنل ورودی سرور چندکاربرهٔ قابل استفاده در این هسته ندارند و
  صریحاً 501 می‌گیرند. گزینه‌های ترجمه‌نشده نیز صریحاً رد می‌شوند؛ از جمله REALITY،
  ECH و تنظیم سفارشی DNS/outbound/sniffing در این هسته.
- پروتکل‌های موجود در هسته‌های دیگر همچنان از همان هسته‌های خود استفاده می‌کنند.

## English

This release embeds the pinned PoriyaVali Mihomo fork in the official V2bX binaries
and Docker builds. Select `mihomo` per node; no separate Mihomo executable is
installed. Eleven authenticated multi-user server protocols integrate with Irboard
accounting, eligibility, live limits, destination policy and certificate loading.
Update Irboard first for the managed-node schema and Webman raw-body fix, then run
`v2bx update 1.10.0`. Existing core selections are preserved.

The real disposable full-stack audit passed 354 distinct checks, including exact
per-user and per-node accounting for 14 server nodes. MDNS has narrower documented
wire coverage. Public ACME issuance/renewal was not validated by the private-CA audit.
Membership edits rebuild the affected listener; limit-only edits preserve sessions.
See the linked setup and audit guides for supported options and reproduction.
