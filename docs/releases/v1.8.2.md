# v1.8.2 — MasterDnsVPN android-multiuser-20261023

Updates the embedded MDNS server from `58baa26` to [MasterDnsVPN `android-multiuser-20261023`](https://github.com/PoriyaVali/MasterDnsVPN/releases/tag/android-multiuser-20261023), commit `25b103d6a5f4039b7a60e3ed0a3d7e99e790cf93`. The dependency is pinned to the immutable Go version `v0.0.0-20261023030011-25b103d6a5f4`.

## Node-side changes

- Faster Base36 decoding with the existing wire format preserved.
- V2 PONG responses omit their unused seven-byte body. Session keys, nonces and full authentication tags are unchanged.
- Keeps the IPv4-first parallel destination dialing fix already shipped in v1.8.1.

No panel configuration or protocol-policy change is required. Existing MDNS domains, keys, user identities and node secrets are preserved.

## Upgrade order and older apps

V2bX can be upgraded before the app's MDNS core. Actual client executables from `android-multiuser-20260928`, `android-multiuser-20261008` and `android-multiuser-20261022` passed V2 data transfers against this server version, including reconnecting after the node restarted. These are local-socket core tests, not phone or public-resolver tests.

The new MDNS release also includes [PR #7](https://github.com/PoriyaVali/MasterDnsVPN/pull/7), the resolver RTT/polling improvements and smaller outgoing PINGs. Those changes execute in the **client** and become available to users when their app core is upgraded. Updating V2bX alone does not change a user's local SOCKS UDP handling or add the 45-second single-server recovery watch. Older clients retain their existing recovery behavior. When the app core is upgraded, include the app-side handling of recovery-time initialization failures described in PR #7.

The previous traffic-efficiency results are workload-dependent; they are not a guarantee of equal throughput or a fixed reduction in carrier bills.

## Install and rollback

Update MDNS nodes with `v2bx update 1.8.2`. Roll back with `v2bx update 1.8.1`. Restarting the node replaces live tunnel sessions, so clients need to reconnect during the upgrade.
