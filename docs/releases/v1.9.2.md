# V2bX v1.9.2 — تفکیک دامنهٔ گواهی از SNI

در نسخه‌های 1.9.0 و 1.9.1، ویزارد ممکن بود SNI پنل یا هدف باقی‌مانده از REALITY را
به‌جای دامنهٔ نود در `CertDomain` ذخیره کند. این نسخه منبع اشتباه را حذف می‌کند.

- برای تنظیم جدید، دامنه از `host` نود پیشنهاد می‌شود؛ هیچ SNI یا هدف REALITY
  خودکار وارد درخواست ACME نمی‌شود. `--cert-domain` انتخاب صریح ادمین است.
- آدرس نود، SNI و دامنهٔ گواهی جدا نمایش داده می‌شوند. نبودن host، آدرس IP یا
  host نامعتبر باعث سؤال دربارهٔ دامنه می‌شود؛ در اجرای بدون سؤال، خطای روشن
  پیش از ذخیره برمی‌گردد. نود REALITY همچنان گواهی نمی‌خواهد.
- دامنهٔ ذخیره‌شدهٔ متفاوت با host نیاز به انتخاب صریح دارد. در پنل قدیمی بدون
  host نیز دامنهٔ ذخیره‌شدهٔ برابر SNI بدون انتخاب صریح دوباره استفاده نمی‌شود.
- اصلاح دامنهٔ گواهی مدیریت‌شده مسیر فایل جدید می‌سازد و مشخصات DNS و حساب ACME
  را حفظ می‌کند؛ گواهی مشترک با نودهای دیگر بازنویسی نمی‌شود. در حالت file، تطابق
  گواهی با دامنهٔ انتخابی بررسی می‌شود. پرچم‌های صریح روش/فایل گواهی اولویت دارند.
- انتخاب دستی mux، Node ID و هستهٔ هر نود مانند نسخهٔ 1.9.1 باقی است.

## ارتقا و اصلاح کانفیگ قبلی

با دسترسی root:

```sh
v2bx update
v2bx menu
```

گزینهٔ ۹ را اجرا کنید. همهٔ نودهای موردنیاز کانفیگ را وارد کنید؛ ویزارد کانفیگ جدید
را می‌سازد و نسخهٔ قبلی را در `/etc/V2bX/config.json.bak` نگه می‌دارد. در تعارض دامنه،
دامنهٔ تحت کنترل خودتان را انتخاب کنید؛ برای ویرایش از `e` استفاده کنید. بعد از ذخیره:

```sh
v2bx restart
```

**آپدیت به‌تنهایی مقدار اشتباه `CertDomain` در کانفیگ موجود را تغییر نمی‌دهد.**
تنظیمات سفارشی را از نسخهٔ پشتیبان بررسی و منتقل کنید؛ فایل‌های گواهی قدیمی حذف نمی‌شوند.

API اصلاح‌شدهٔ Irboard روی شاخهٔ `main`، فیلد `host` را برای تمام پروتکل‌های TLS
می‌فرستد و SNI اشتراک را تغییر نمی‌دهد. برای تشخیص کامل دامنه، پنل را نیز با روش
معمول خودش به‌روز کنید. V2bX جدید با پنل قدیمی هم کار می‌کند، اما در نبود host
دامنه را صریح می‌پرسد.

در TLS معمولی، نام مورد اعتبارسنجی کلاینت باید در SAN گواهی باشد. گواهی دامنهٔ شما
SNI سایت دیگری را معتبر نمی‌کند؛ در صورت اختلاف، تنظیم SNI/نام اعتبارسنجی در پنل
باید بررسی شود. اعتبارسنجی TLS و رمزگذاری ترافیک ضعیف نمی‌شوند. MDNS تغییری ندارد.

## بررسی‌ها

آزمون‌های ویزارد و API شامل TLS در AnyTLS، VLESS، VMess (کلیدهای فعلی و قدیمی)،
Trojan، TUIC و Hysteria 1/2، دامنهٔ متفاوت از SNI، host گمشده/IP/نامعتبر، اصلاح
کانفیگ قبلی، حفظ مشخصات DNS، فایل گواهی صحیح و نامطابق و قطع ورودی هستند.
پاسخ‌های واقعی HTTP پنل با SQLite در حافظه تولید و در تست Go مصرف می‌شوند.
آزمون Race و بررسی استاتیک Go موفق بودند. باینری با همهٔ هسته‌های ریلیز از مسیر
واقعی گزینهٔ ۹، AnyTLS و Hysteria2 را با گواهی محلی معتبر راه‌اندازی کرد؛ بررسی
نام درست موفق و نام نامطابق رد شد، MDNS پاسخ DNS داد و سرویس تمیز متوقف شد.
پنل ۱۹۹ آزمون و ۱۵۹۰ assertion را با استثنای پنج آزمون قدیمی GoogleAuth عبور داد.
صدور روی Let's Encrypt عمومی در محیط آزمایش اجرا نشده است.
