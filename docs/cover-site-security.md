# سایت پوششی و محدودکردن هزینهٔ اسکن

این تغییر، پاسخ نودهای پشتیبانی‌شده به درخواست عادی وب را کامل‌تر و پایدارتر می‌کند.
هدف، کاهش نشانه‌های سادهٔ شناسایی فعال و محدودکردن مصرف منابع سایت عمومی است؛
تضمین شناسایی‌نشدن توسط ربات‌ها یا GFW نیست. TLS، اعتبارسنجی کاربران و رمزگذاری
ترافیک پروکسی برای ساخت سایت ضعیف یا غیرفعال نمی‌شوند.

## تنظیمات ویزارد و نود

بدون تنظیم اضافی، سایت داخلی صفحهٔ اصلی، سه مطلب قابل بازشدن، صفحهٔ درباره، CSS،
favicon و robots.txt دارد. عنوان، محتوا، تاریخ و ETag با restart یا تغییر شناسهٔ نود
عوض نمی‌شوند. دامنهٔ تنظیم‌شدهٔ گواهی، و سپس نام داخل گواهی، هویت سایت را مشخص می‌کند؛
نودهای یک دامنه با تنظیمات یکسان همان سایت را نشان می‌دهند. Host یا SNI دریافتی از
کاربر، فایل یا مقصد شبکه‌ای انتخاب نمی‌کند.

برای محتوای اختصاصی، پوشه‌ای فقط شامل فایل‌های عمومی سایت خودتان بسازید و
`index.html` را در ریشه قرار دهید:

```sh
V2bX configure --panel https://panel.example.com \
  --api-key-file /root/irboard-api-key --nodes vless:1,hysteria2:2 \
  --cover-root /var/www/node-public --output /etc/V2bX/config.json
```

`--cover-title` عنوان قالب داخلی را تغییر می‌دهد؛ HTML اختصاصی بازنویسی نمی‌شود.
`--cover-tcp=false` فقط شنوندهٔ HTTPS همراه نود UDP را غیرفعال می‌کند. در تنظیمات
دستی، این بلوک را داخل عضو موردنظر از `Nodes` قرار دهید:

```json
{
  "Decoy": {
    "Root": "/var/www/node-public",
    "Title": "My Notes",
    "MaxConnections": 128,
    "RequestsPerSecond": 128,
    "ServeTCP": true
  }
}
```

حذف `Root` یعنی استفاده از قالب داخلی. صفر یا حذف محدودیت‌ها مقدار پیش‌فرض را
انتخاب می‌کند. سقف تنظیم‌پذیر اتصال ۴۰۹۶ و نرخ درخواست ۱۰۰۰۰ در ثانیه است.
`DecoySite: false` گزینهٔ قدیمی برای خاموش‌کردن سایت خودکار در هستهٔ مربوطه است؛
fallback یا masquerade سفارشی اپراتور جایگزین نمی‌شود.

## پوشش پروتکل‌ها

| نود | رفتار درخواست عادی وب |
| --- | --- |
| Xray، VLESS یا Trojan روی TCP+TLS | fallback خودکار HTTP/1.1 و HTTP/2، وقتی fallback سفارشی وجود ندارد؛ VLESS با رمزگذاری افزوده مستثناست |
| Sing، AnyTLS با TLS معمولی | سایت پشت fallback موجود |
| Sing، Hysteria2 | سایت در HTTP/3 و HTTPS روی TCP همان IP و شمارهٔ پورت |
| هستهٔ اختصاصی Hysteria2 | همان پوشش HTTP/3 و TCP، در حالت masquerade پیش‌فرض |
| Sing، TUIC یا Hysteria نسخهٔ اول با TLS | سایت HTTPS روی TCP همان IP و شمارهٔ پورت؛ پروتکل UDP به HTTP/3 تبدیل نمی‌شود |
| REALITY | مسیر relay به مقصد تنظیم‌شده حفظ می‌شود |
| Sing، VLESS/Trojan؛ VMess؛ Shadowsocks؛ انتقال‌های WS/gRPC و سایر حالت‌ها | fallback عمومی تازه‌ای برای این حالت‌ها اضافه نشده است |
| MDNS و TrustTunnel | این سایت، جایگزین پروتکل DNS یا endpoint اختصاصی TrustTunnel نمی‌شود |

ویزارد در حالت `--core auto` برای VLESS بدون رمزگذاری افزوده و Trojan روی TCP+TLS،
Xray را انتخاب می‌کند؛ انتخاب صریح هسته مقدم است. محدودیت fallback در Sing Trojan
با بازکردن دسترسی کاربران به مقصدهای خصوصی دور زده نشده است.

شنوندهٔ تازهٔ HTTPS فقط برای نودهای UDP پشتیبانی‌شده با گواهی فایل فعال می‌شود و
حداقل TLS 1.2 را می‌پذیرد. TCP و UDP می‌توانند یک شمارهٔ پورت داشته باشند. اگر آن
پورت TCP اشغال باشد یا گواهی سایت بارگذاری نشود، سرویس موجود متوقف نمی‌شود؛ هشدار
ثبت می‌شود و نود UDP ادامه می‌دهد. سایت همراه با حذف یا بستن نود بسته می‌شود.
این تغییر هیچ رکورد DNS یا قانون فایروالی نمی‌سازد.

## مرز فایل‌ها و منابع

فایل‌ها هنگام ایجاد نود به حافظه خوانده می‌شوند؛ درخواست وب خواندن آزاد از دیسک،
directory listing، اجرای کد یا درخواست به سرور دیگری ندارد. symlinkها، مسیرهای
مخفی، کلیدها، فایل‌های تنظیمات، JSON و متن‌های عمومی با پسوند txt سرو نمی‌شوند؛
فقط robots/security/humans/ads.txt و پسوندهای رایج سایت مانند HTML، CSS، JS، تصویر،
فونت و XML مجازند. حداکثر ۲۵۶ فایل عمومی، ۲ MiB برای هر فایل و مجموع ۱۶ MiB محتوای
فشرده‌نشده پذیرفته می‌شود؛ پیمایش بیش از ۴۰۹۶ ورودی نیز رد می‌شود. حافظهٔ واقعی
شامل نسخهٔ gzip و سربار ساختارها هم هست. تغییر فایل‌ها با ایجاد مجدد نود اعمال می‌شود.
این allowlist جای بررسی محتوای فایل‌های عمومی توسط اپراتور را نمی‌گیرد.

سایت به‌طور پیش‌فرض ۱۲۸ درخواست در ثانیه با burst برابر ۲۵۶ و حداکثر ۶۴ درخواست
هم‌زمان می‌پذیرد؛ اضافه‌بار پاسخ 503 و Retry-After می‌گیرد. هر شنوندهٔ متعلق به سایت
حداکثر ۱۲۸ اتصال، مهلت خواندن header و خواندن/نوشتن، و محدودیت stream و buffer در
HTTP/2 دارد. سهمیهٔ handler سایت در Sing بین TCP و HTTP/3 مشترک است؛ در هستهٔ
اختصاصی Hysteria2، هر handler سهمیهٔ خودش را دارد. این سهمیه‌ها روی ترافیک کاربر
احرازشده اعمال نمی‌شوند. مسدودسازی بر اساس IP یا User-Agent اضافه نشده است تا
کاربران پشت NAT مشترک با یک اسکنر قطع نشوند.

HTML و خطاها از قبل ساخته می‌شوند؛ gzip در شروع ساخته و ETag از محتوا محاسبه می‌شود.
GET، HEAD، درخواست شرطی 304 و Range پشتیبانی می‌شوند. سرآیند جعلی nginx حذف شده است.
TLS سایت همراه از گواهی cache‌شده استفاده می‌کند؛ کلید در هر اتصال از نو تجزیه نمی‌شود.

## اعتبارسنجی و محدودیت‌ها

آزمون‌ها شامل HTTPS واقعی با بررسی hostname و ریشهٔ گواهی، HTTP/2، HTTP/3، یکسان‌بودن
محتوای TCP و UDP در Sing Hysteria2، بسته‌شدن سایت با نود، تداخل پورت، فایل‌های حساس،
symlink، فشرده‌سازی و پاسخ‌های شرطی هستند. پس از پرشدن سهمیهٔ سایت نیز انتقال واقعی
کاربر معتبر VLESS آزمایش می‌شود. بیلد کامل، بیلد با تگ‌های ریلیز، vet و مجموعهٔ
Race اجرا شده‌اند. آزمون‌های TLS فایل در Xray جداگانه بدون Race اجرا می‌شوند، چون
وابستگی Xray در مسیر تعویض دوره‌ای گواهی یک race از پیش موجود دارد؛ این تغییر آن
مشکل وابستگی را اصلاح نمی‌کند.

قالب‌های داخلی محدود و کدشان عمومی است؛ محتوای مستقل سایت خودتان اشتراک اثرانگشت
را کمتر می‌کند، ولی IP، DNS، گواهی عمومی، ClientHello، رفتار TLS/QUIC و الگوی ترافیک
همچنان قابل مشاهده‌اند. هزینهٔ handshake پیش از رسیدن به handler و حملهٔ حجمی شبکه
با سهمیهٔ وب حذف نمی‌شود. هیچ آزمون میدانی روی GFW یا شبکهٔ اپراتورهای ایران در این
محیط انجام نشده و گواهی دلخواه به‌خودی‌خود پروتکل پروکسی را شبیه وب نمی‌کند.
